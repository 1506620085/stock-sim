# 性能与架构优化清单

> 基于当前仓库（`apps/web` + `apps/api`）代码审查整理。  
> 目标：运行更流畅、包体更小、结构更易维护。  
> 使用方式：后续按优先级逐步指挥落地；本文件只做清单，不自动改代码。

---

## 1. 现状速览

| 区域 | 技术 | 说明 |
|------|------|------|
| 前端 | React 19 + Vite 6 + TS | 主复杂度集中在复盘图与页面 |
| 后端 | FastAPI + SQLModel + PostgreSQL | 结构较清晰，统计/估值查询是瓶颈风险 |
| 共享包 | 无 `packages/` | 类型与公式在 feature 内交叉引用 |
| 样式 | 单文件 `styles.css` | 约 **7700+** 行 |

### 前端体量 Top（约）

| 文件 | 行数 | 问题倾向 |
|------|------|----------|
| `apps/web/src/styles.css` | ~7750 | 难维护、重复规则多 |
| `features/replay/ReplayPage.tsx` | ~1700 | 状态过多、职责过重 |
| `features/replay/KLineChartPanel.tsx` | ~1500 | 图表生命周期/同步过重 |
| `features/calculators/CalculatorsPage.tsx` | ~1370 | 四计算器挤在一文件 |
| `features/notes/NoteEditor.tsx` | ~1350 | TipTap 副作用多 |
| `features/settings/SettingsPage.tsx` | ~860 | 设置项堆叠 |

### 路由加载现状

`App.tsx` **静态 import** 全部页面（复盘 / 自选 / 笔记 / 计算器 / 统计 / 设置 / 训练），**没有** `React.lazy`。

后果：即使从不打开笔记，也会带上 TipTap；从不打开统计，也会带上 echarts 相关代码。

## 2. 优化优先级总表

| 优先级 | 方向 | 主要收益 |
|--------|------|----------|
| **P0** | 路由懒加载、图表 effect 拆分、ReplayPage 拆分、CSS 模块化 | 首屏/交互流畅、可维护性 |

## 3. P0 — 高收益（建议先做）

### 3.1 路由级代码分割

**现状：** `App.tsx` 同步引入全部页面。  
**建议：**

- 复盘（默认页）+ `klinecharts` 可保持 eagerly load
- 懒加载：`NotesPage`（TipTap）、`CalculatorsPage`、`StatsPage`（echarts）、`SettingsPage`、`WatchlistPage`、`TrainingPage`
- 配 `Suspense` + 轻量 loading

**收益：** 首包显著减小，冷启动更快。  
**涉及：** `apps/web/src/App.tsx`

---

### 3.2 K 线图表 effect / 同步管线拆分

**现状：** `KLineChartPanel.tsx` 中大数据 effect 依赖面过宽（数据、指标、复盘日、图例偏移、显示开关等），容易触发：

- `resetData()`
- `removeIndicator()` + 全量重建

**建议拆成独立管线：**

1. **init / dispose**（仅挂载一次）
2. **数据更新**（`chartData` / symbol / period）
3. **指标同步**（主图/副图参数变化）
4. **样式**（网格、十字光标、图例 offset）
5. **滚动定位**（复盘日 / recenter）
6. **叠加层**（B/S/L、R、持仓区、成本线）

**收益：** 拖动、切换指标、改复盘日时更跟手。  
**涉及：** `features/replay/KLineChartPanel.tsx`

---

### 3.3 拆分 `ReplayPage`

**现状：** 约 49 个 `useState`，交易 / 会话 / 盈亏 / 工具栏 / 导入导出挤在一页。

**建议抽出：**

| 模块 | 内容 |
|------|------|
| `useReplaySession` | 会话加载、切换、删除、复盘日 |
| `useReplayTrades` | 买卖记录 CRUD、快速仓位 |
| `useReplayChartData` | bars 聚合、hideFuture、周期 |
| 子面板文件 | `TradePanel` / `PnlPanel` / `TradeHistoryPanel` / `TradeReviewPanel`（已有内联组件可外移） |

可选：用 `useReducer` 合并强相关状态，减少无效重渲染。

**涉及：** `features/replay/ReplayPage.tsx`

---

### 3.4 拆分巨型 `styles.css`

**现状：** 全站样式一锅端，前缀混杂（`kb-*`、`chart-*`、`trade-*`、`notes-*`…）。

**建议按域拆分后在入口汇总，例如：**

```
styles/
  base.css
  components.css
  replay.css
  notes.css
  calculators.css
  stats.css
  settings.css
```

或逐步引入 CSS Modules（组件级优先）。

**收益：** 改样式冲突少、按需理解成本低；长期可配合路由懒加载减少无用 CSS 心智负担。

## 4. P1 — 中收益

### 4.1 十字光标悬停不要打爆整页

**现状：** `onHoveredBarIndexChange` → `ReplayPage` state → 行情摘要等整树重渲染。

**建议：**

- 悬停 index 放 ref，或仅 `QuoteSummary` 本地订阅
- 或用轻量事件总线 / `useSyncExternalStore`

**涉及：** `KLineChartPanel.tsx`、`ReplayPage.tsx`、`QuoteSummary.tsx`

---

### 4.2 统计接口缓存 / 预聚合

**现状：** `/api/stats/summary` 易变成「拉全会话 + 交易 + 复盘 + 日记」内存聚合。

**建议：** 短 TTL 缓存、或物化摘要表 / 增量维护。

**涉及：** `apps/api/app/routers/stats.py` 及相关 service

---

### 4.3 前后端盈亏逻辑统一

**现状：** 前端 `ReplayPage` 内计算持仓/盈亏，后端 `services/replay/pnl.py` 另有一套，存在漂移风险。

**建议：** 以 API 为准，或抽出共享公式模块（长期可进 `packages/`）；前端展示尽量吃接口结果。

---

### 4.4 antd 体积控制

**现状：** 主要用 DatePicker、ColorPicker，但易拖大主包。

**建议：** 确认按需引入；评估自研轻量日期/色板替代。

**涉及：** `components/AppDatePicker.tsx`、`MainIndicatorSwitcher.tsx`

---

### 4.5 导航切换时保留复盘页实例

**现状：** `PageContent` 条件渲染，离开复盘会销毁图表，回来重新 `init`。

**建议：** 对复盘路由使用隐藏挂载（`display:none` / 缓存 outlet），避免重复初始化 klinecharts。

---

### 4.6 API 客户端与类型收敛

**现状：** `replay/api.ts`、`settings/api.ts`、`notes/api.ts` 分散；类型多在 feature 内。

**建议：** `src/api/` + `src/types/`（或后续 `@stock-sim/shared-types`）。

## 6. 后端注意点（摘要）

| 点 | 说明 |
|----|------|
| 统计全量扫描 | 数据变大后 `/summary` 会变慢 |
| MTM 拉 bar | 多标的 × 复权 × 区间，注意单次查询体积 |
| Akshare 同步 | 外部源慢、重试；需限流与进度反馈 |
| 缓存几乎空白 | 除少量 `@lru_cache`（设置/存储工厂）外无业务缓存 |
| 搜索副作用 | 标的搜索路径上可能写库修名，需谨慎 |

后端目录分层（router / service / provider）整体健康，优先做「读路径缓存与聚合」而非大重构。

## 7. 建议落地顺序（供后续指挥）

可按下面步骤逐步做（每步可单独 PR/提交）：

1. **路由懒加载**（改动小、收益大）  
2. **抽取 `utils/format` + 统一 Tooltip**（低风险热身）  
3. **KLineChartPanel 同步管线拆分**（核心流畅度）  
4. **ReplayPage 拆 hooks / 子面板文件**  
5. **styles.css 按域拆分**  
6. **悬停行情状态下沉**  
7. **统计接口缓存**  
8. **FeeTemplateSelect / IndicatorParamsDialog 等业务组件抽取**  
9. **盈亏逻辑前后端统一**  
10. （可选）workspace + shared-types / OpenAPI client

## 8. 非目标（本阶段不做）

- 不为优化而引入过重状态库（除非 Replay 状态拆分后仍难控）  
- 不急于上完整 `packages/` monorepo（先 `src/shared` 即可）  
- 不重写 klinecharts / 不换图表库  
- 不在无测量情况下做微优化（先解决重建图表、主包过大等问题）
